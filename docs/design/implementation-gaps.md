## この文書の目的

設計意図（「どう実現したいか」）と現状コードの差分を記録する。
`reid_architecture.md` の「現状との差分」表、`DATAFLOW.md` の「既知の課題」と重複する項目もあるが、
本文書は 2026-10-19 時点のコード確認で**改めて残存を確認した項目**と、
**既存文書に未記載だった新規発見**を一箇所にまとめたものである。

差分が解消されたらその行を削除し、該当する設計文書（`reid_architecture.md` 等）の現状記述へ統合する。

### 設計意図の確認結果（2026-10-19 時点）

本一覧の前提となる、開発者への確認で判明した設計意図。

| # | 確認事項 | 結論 |
|---|---|---|
| 1 | 文書記載の差分の扱い | すべて「未修正の課題」。原則ずれとして扱うが、現状のままが設計的に優れる項目は "残す" 判断も検討する |
| 2 | ファイル名 | 実態と対応していない（`camtest.py` が本番コードか検証用か判別不能）。命名・構成の整理が必要 |

| 4 | スタッフ/来場者判定 | スタッフ類似度と来場者類似度を**両方算出し、高い方を採用**（どちらも閾値未満なら新規来場者）。argmax 方式が意図 |
| 5 | ブース定義 | 現状の左右二分割は暫定。運用時に実ブース形状へ切り替える。「ブース外」概念は使わず、全画面を常にいずれかのブース（A/B）として表示する |

## 解消状況（2026-11-01, ブランチ `fix/design-gaps`）

10/19 時点で挙げた A-1〜A-10 と B の全項目、および 11/01 に追加で見つかった次の 2 件を解消した。

- A-11: 照合済みトラックが閾値を下回ると既存来場者のプールが 1 枚で上書きされる
- A-12: スタッフ ID の採番ずれによる既存スタッフの上書き

照合フローは `reid_architecture.md` §5 の形（照合は新しい track_id の出現時のみ、画面内の人は照合相手から除外、滞在は real_id 単位）へ移行した。
§8 の「照合とプール更新の分離」案（15 フレームごとにプールへ追加）も実装したが、**動画での効果検証は未実施**である。
